## 01 / Your weekly rhythm

**Your focus:** a prepared team, an agreed setlist, and clear communication.

### Four checks to keep things moving

| When | Check |
| --- | --- |
| Start of the week | Upcoming events, overdue setlists, pending reviews, leave, and replacements. |
| Before rehearsal | Confirmed team, song order, complete charts, keys, and shared notes. |
| Before the service | Latest chart updates, Stage/Tech participants, attendance, and last-minute changes. |
| After the event | Attendance exceptions, observations, follow-ups, and the next event. |

### Where to go

| I need to... | Open |
| --- | --- |
| Plan a session | Events, then the event |
| Review a proposal | Leadership > Setlist Queue |
| Review leave or a replacement | Leave Queue / Swap Requests |
| Check people and roles | Team Roster |
| Review attendance or conduct | Accountability |
| Change church rules | Admin Settings |
| Change reminder wording | Admin Settings > Notification settings |

### Three differences that matter

- **Confirmed assignment** means the person accepted. It does not mean they checked in.
- **Notification sent** does not mean the person responded. Check the actual response.
- **Only me** changes your chart experience. **For the team** changes shared preparation.

**Taking over church administration too?** Keep the Music Director role and add Administrator access. The next page explains the difference.

## 02 / Roles and access

**Music Director is a leadership role. Administrator is a separate switch.** Titles do not create a ranked access ladder.

### What the six leadership roles share

Event creation/editing/rescheduling, setlist management/review, leadership announcements, and viewing Team Roster.

| Role | Approve leave | Manage accountability | Manage members / roles |
| --- | --- | --- | --- |
| Music Director | Yes | Yes | Grant needed |
| Production Director | Yes | Yes | Yes |
| Admin Coordinator | Yes | Yes | Grant needed |
| Stage Director | Grant needed | Grant needed | Grant needed |
| Setlist Coordinator | Grant needed | Grant needed | Grant needed |
| Admin | Yes | Yes | Yes |

“Grant needed” means the role alone does not provide that action. Viewing a page does not grant every control on it. An event's **Song Leader** assignment is an event responsibility, not ministry-wide leadership.

### What Administrator adds for the Music Director

- Member/role management and granting access to other members.
- Church policies, attendance QR administration, and notification settings.
- Notification activity, member reflections, and pending assignment reminders.

Keep the Music Director role as well: some event/music screens still require a leadership role. The ministry role named **Admin** has extra tools, but is not the same as Administrator.

### Two limits to know

**Delegated grants:** Approve leave/swaps, Review setlists, Manage members/accountability/notifications, and Archive events. They add access; unticking one does not remove access already supplied by a role. Some screens still check named roles, so verify the intended action in the person's account.

**Platform Owner:** separate again. Event **Move to Past / Upcoming** currently requires this access. Neither Administrator nor the **Archive events** grant unlocks those controls yet.

## 03 / Useful shortcuts

### Events: hold to open move options

1. In **Events**, find an event whose schedule has ended or which is already in Past.
2. **Hold the card for about 0.6 seconds without dragging.** On desktop, right-click.
3. Choose **Move to Past events** or **Move to Upcoming**, then confirm.

**Currently Platform Owner only.** An unended future event is not eligible. Scrolling cancels the hold. Eligible actions also appear in the event's Actions menu and on desktop list cards.

**Finished is different from Past.** An ended event can remain in Upcoming until moved. Moving it does not change its date or delete it. Use **Delete event** only when you intend deletion.

### Everyday gestures

| Where | Shortcut | Result |
| --- | --- | --- |
| Global search | Ctrl+K / Cmd+K | Open search; Escape closes it. |
| Stage chart | Left / Right arrow | Previous / next song when not editing or using a picker. |
| Mobile chart | Swipe between songs | Navigate the set; use the song picker for a direct jump. |
| Chart text | Pinch; desktop Alt+wheel | Change font size. Display also has size controls. |
| Chart line with notes enabled | Hold briefly; double-click | Open line notes. Hold the text, not a chord. Keyboard: Enter/Space on a focused note trigger. |
| Conversation list | Hold; desktop right-click | Open Chat Options. |
| Individual message | Hold; desktop right-click | Show available message actions. |

**Read the scope in chat:** Archive for Me, Archive for Everyone, Leave Chat, and Delete Chat are different actions. Available options depend on access and ownership.

## 04 / Managing events

**Open:** Events > select the event.

### Before you invite the team

1. Check event type, date, start/end time, title, and Song Leader where relevant.
2. Check whether a setlist is required. Revamp and other non-music sessions can run without one.
3. Check the event's actual submission deadline. Event-type defaults can differ.
4. Review leave/coverage notices, then assign the correct people and roles.
5. Watch responses. **Pending is not confirmed.** An invitation to attend is different from a serving assignment.

### Choose the right action

| Action | Use it for |
| --- | --- |
| Edit event | Changing event details. |
| Reschedule event | Changing the schedule and asking assigned members to confirm again. Review the old/new dates afterward. |
| Assignment reminder | Following up on pending assignment responses; requires Admin, Administrator, or Platform Owner access. |
| Setlist reminder | Following up on an unsubmitted proposal near its deadline or overdue. The event-detail control uses a three-day window and a cooldown. |
| Move to Past / Upcoming | Changing listing status; currently Platform Owner only. |
| Delete event | Removing the event, not routine completion. |

A setlist already awaiting review needs a reviewer, not another submission reminder. Before sending a reminder, check which people it will reach.

### After the event

Review attendance exceptions. Use **Past-event Observations** where shown to capture useful follow-ups; give assigned follow-ups an owner and due date.

**Before leaving:** check that the date, team, and setlist state saved correctly. If an action fails, preserve the draft and inspect the result before retrying.

## 05 / Preparing a setlist

**Open:** Leadership > Setlist Queue, then the event.

### Know the next step

| Status | Next step |
| --- | --- |
| Draft | Finish the songs, order, charts, and keys; submit for review. |
| Pending review | Review and respond. |
| Revision requested | Explain specific changes; the Song Leader edits and resubmits. |
| Approved | Use it for preparation; communicate later changes. |
| Rejected | Read the explanation; rework/reset to Draft if a proposal is still needed. |

### Before approving

- Check the service flow, transitions, and intended arrangements.
- Check complete lyrics/chords, song order, lengths, and suitable keys. Missing lyrics can block submission.
- Read revision comments and check that requested changes are resolved.
- Confirm everyone is preparing from the intended event or linked rehearsal set.

### Before changing a key or note

**Only me:** personal reading/transposition or private notes. Saved private notes can sync to the same account's other devices.

**For the team:** the agreed shared key or shared preparation notes. Use this only when the team should receive the change and you have permission to save it.

A library song, an event's arrangement/key, and your display settings have different scopes. Read the editor label before saving. A recovery draft does not prove the shared save succeeded.

**Library tip:** Songs, Sets, and Videos hold reusable material. Broad cleanup such as merging duplicate songs requires Admin, Administrator, or Platform Owner access.

## 06 / Live Mode and Tech Mode

**Before starting:** agree on the event everyone will open. Linked rehearsal/service charts do not automatically share an event cue queue.

### Set up, then play

1. Confirm assignments. Audio/Lights/Visuals use Tech; performers use Stage. Eligibility depends on confirmed event assignments. Admin-enabled preview can choose either.
2. Set readable text size and the lyrics/chord view you need.
3. Check shared keys and notes. Open the panels you want to keep available.
4. Navigate songs with arrows, mobile gestures, or the picker.

The set's notes are cached/preloaded for smoother switching. Open toolbar/settings panels should remain open across songs.

### Bringing in changes

When **New updates available** appears, refresh at a suitable pause. After saving a team change, tell everyone when to refresh so they use the same version.

Use **Edit** for a deliberate content change, then save and check the result. Use Display, pinch, or Alt+wheel for font size.

### Understand cue status

| Status | Meaning |
| --- | --- |
| Live / connected | Connection available; no human acknowledgment yet. |
| Received/saved | Cue reached the shared queue. |
| Seen | Tech acknowledged seeing it. |
| Adjusting | Tech is working on it. |
| Done | Tech marked it complete; confirm the result if needed. |

Keep cues concise and targeted. Check failed/retry indicators instead of repeatedly sending. Tech can use history to reopen a request; instructions back to performers may need acknowledgment too.

**Before the first service:** do an agreed rehearsal check on the real devices. Keep verbal communication available. Check battery/auto-lock settings; caching does not guarantee full offline operation.

## 07 / Leave and replacements

**Open:** Leadership > Leave Queue / Swap Requests.

### Reviewing leave

1. Read dates, reason, affected events, and overlapping requests.
2. Separate **approved leave** from **pending requests** when planning coverage.
3. Check which serving roles need coverage, then approve or deny with a respectful explanation.

**Saturday can affect Sunday preparation.** If leave ends on Saturday, the next Sunday's event can appear as potentially affected. This does not extend the leave dates or automatically mark the member absent on Sunday.

### What members see

The **Before you submit** card asks members to consider whether their commitment is important and cannot reasonably be moved. It may show repeated-request and overlapping-leave reminders. Members tick an acknowledgment before submitting; changed dates/guidance can require ticking it again.

This is a reminder, not a requirement to contact a leader first. Other members' private reasons are not exposed in the overlap notice. The repeated-request check counts relevant requests, not total days away.

Church policy controls approval, reasons, notice periods, date ranges, and whether swaps are allowed.

### Replacing a member

1. A member requests a substitute/swap through the assignment workflow.
2. The proposed replacement responds; leadership review may wait for that response.
3. Review availability and the affected assignment(s), then approve or reject.
4. Open the event and verify the team afterward. A swap changes both sides.

**Leave approval does not fill an empty slot.** Leave, replacements, and attendance are separate records. If a replacement action fails, inspect the assignments before retrying.

## 08 / Attendance and follow-up

**Open:** Leadership > Accountability.

### Keep these records separate

| Record | What it tells you |
| --- | --- |
| Assignment response | The member accepted or declined. |
| Attendance | The member completed check-in, and when. |
| Accountability review | The record was reviewed and follow-up considered. |

### On the event day

- Make sure the correct church/event QR check-in is available. QR administration needs Administrator or Platform Owner access.
- Ask members to finish check-in and check its success state; opening the scanner is not completion.
- Check the configured attendance window and grace period before interpreting Late or unavailable check-in messages.

### When a record needs review

Use **Attendance** for monitoring and period records; use **Conduct** for conduct follow-up. Music Director has the standard management access for these reviews.

Check the event, selected period, recorded status, and notes. Automatic absence or flagged records may need consideration. Use the appropriate review action and record why a correction or exception is justified.

### Wider changes need care

**Attendance consideration/reset** requires Administrator or Platform Owner, a reason, and scope confirmation. Check the period and affected members. It is not the usual fix for one incorrect record.

**Included in Attendance / Surveys / Assignments** settings affect participation, not just appearance. Give a reason for exclusions.

**Keep personal details private.** Use leave reasons, leadership notes, conduct records, and reflections for appropriate follow-up. A dashboard flag is a prompt to review the situation, not the whole story.

## 09 / Messages and reminders

### Pick the right place

| Need | Use |
| --- | --- |
| Information people should find later | Announcements; check the audience/leadership-only setting. |
| A discussion | Event or group chat. |
| An immediate stage/tech request | Live Mode cues. |
| A missing response or proposal | The matching reminder on the event. |

### Change Revamp reminder wording

1. Open **Admin Settings > Notification settings**.
2. Find **Event invitations & reminders** and choose **Revamp Session**.
3. Choose invitation, attendance response, day-before, or event-day reminder.
4. Edit the wording, or select **Use simple wording**, then review it.
5. **Save the category/rules.** A preset alone does not save.

Example without organizer wording: “You're invited to [event] on [event date]. Please confirm or decline your attendance in ServeSync.” Only use placeholders supported by that rule.

Access requires Administrator, Platform Owner, or **Manage notifications**. Automatic setlist reminder timing is separately configured in **Admin Settings > Setlist reminder schedule**.

### Before sending or interpreting an alert

**Remind and Send test send real messages.** “Send test to all admins” reaches real administrators. Check recipients first.

**Notification activity** is available to Admin, Administrator, and Platform Owner; Manage notifications alone does not grant the report. Provider acceptance does not prove device display. An open does not prove understanding, and marking all as read does not record an open.

No recorded open can reflect an older client or offline device. Check the actual response before assuming someone ignored a request.

## 10 / Team and church settings

**Open:** Team Roster > expand the member.

### Granting the incoming director access

An existing Administrator keeps the member's **Music Director** role and turns on **Access & inclusion > Administrator** if church administration is part of the handover.

The Administrator switch updates separately. Other access/inclusion edits use **Save**. Check success, then verify access in the incoming director's own account.

### Understand the controls

| Control | Purpose |
| --- | --- |
| Ministry roles | Serving responsibilities and role-based access. |
| Administrator | Organization administration, separate from the Admin ministry role. |
| Delegated capabilities | Selected extra access; see the limits on PDF page 3. |
| Included in Attendance / Surveys / Assignments | Participation in those workflows; explain exclusions. |
| Password reset | Emails a link so the member sets their own password. |
| Remove member | Removes church membership/access; more than removing a role. |

### Review these settings together

- **Event/setlist defaults:** event types, times, setlist requirement, service format, and submission deadlines.
- **Reminders:** enabled timing, overdue follow-up, escalation, and wording.
- **Leave/swaps:** approval, reason, notice, date ranges, and swap permissions.
- **Attendance:** opening window, grace, scan validity, reminders, and automatic absence timing.
- **Other:** Tech Mode quick messages, church profile, reflection prompts, and who reviews responses.

Save the relevant section and check the result. New defaults do not automatically rewrite existing events.

**Use individual logins.** Agree separately who handles billing, hosting, database, and domain ownership; an app role does not transfer those accounts.

## 11 / Handover and quick help

### Complete together

- [ ] Incoming director signs in to the correct church with their own account.
- [ ] Music Director role and agreed Administrator access are present.
- [ ] Verify event editing, setlist/leave review, team management, and notification settings. Cancel practice edits; avoid real test messages.
- [ ] Review upcoming events, pending requests, follow-ups, and church policies.
- [ ] Walk through Live Mode, note/key scope, refresh, and Tech acknowledgments.
- [ ] Agree on a backup administrator and technical contact.
- [ ] Decide who handles Move to Past while it remains Platform Owner only.
- [ ] Once access works, another Administrator removes the outgoing head's agreed access/roles. Self-removal is blocked; at least one Administrator must remain.
- [ ] Resolve retained Platform Owner access and any technical ownership transfer separately.

### Quick help

| Problem | First check |
| --- | --- |
| Missing leadership tools | Exit Member/Song Leader preview; check account, church, roles, and Administrator access. |
| A visible menu has a denied action | Check the specific action's access. Delegated grants do not reach every screen yet. |
| Event hold does nothing | Platform Owner access, eligible ended/past event, and a steady hold. |
| Chart changes are missing | Correct event/setlist, successful shared save, then refresh. |
| Request still pending | Actual recipient response, not just notification delivery. |
| Save failed | Keep the draft, check connection/error, and inspect existing data before retrying. |
